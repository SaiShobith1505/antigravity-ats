# BOOSTCV ATS Scoring Regression Investigation

This report details the investigation into why the same BOOSTCV-generated resume scored **91% in the Builder** but only **77% in the ATS Scanner**.

---

## 2. Root Cause Analysis

### Discrepancy 1: `isBoostCV` Identification Loophole
* **Mechanism**: In `scoring-engine.ts`, a boolean `isBoostCV` determines if the resume is a "clean" BOOSTCV document. If `isBoostCV` is `true`, the engine skips several strict formatting layout penalty checks (like hidden tables, Canva spacers, and grid layouts).
* **Defect**: 
  - The Builder text generator (`serializeResumeDataToText`) *always* appends `"ATS SAAS Compiler BoostCV"` to the text. Therefore, `isBoostCV` is **always true** in the Builder.
  - The PDF template does *not* render the hidden text `"ATS SAAS Compiler BoostCV"` on the page. Therefore, when the PDF is exported and parsed by `PdfReader`, `isBoostCV` is evaluated as **false**.
  - As a result, the Scanner runs formatting checks on the PDF that the Builder completely skipped.

### Discrepancy 2: Substring Matching False Positives
Because the Scanner ran formatting checks on the PDF, it matched characters globally without word boundaries:
1. **Hidden Table Check**:
   - *Regex/Trigger*: `lowerText.includes("table")`
   - *Triggering Word*: `"executable"` (contains the substring `"table"`).
   - *Penalty*: `-15%` formatting score.
2. **Grid Layout / Canva Separator Check**:
   - *Regex/Trigger*: `lowerText.includes("|")`
   - *Triggering Character*: `"|"` (used as a clean visual divider in the Technical template header).
   - *Penalty*: `-20%` formatting score.

### Discrepancy 3: Readability Section Header Hijacking
* **Mechanism**: The chronological order check maps headers `["education", "experience", "projects", "skills"]` and verifies their indices are sorted.
* **Defect**: The user has `"EduSkills"` in their experience company name. The substring `"skills"` matched inside `"EduSkills"` (index ~400) instead of the actual `"TECHNICAL SKILLS"` header (index ~2000). This caused the engine to flag the sections as out-of-order.

### Discrepancy 4: Uncalibrated Category Breakdowns
* **Mechanism**: In `src/app/api/ats/check/route.ts`, when the Gemini AI path is active, the engine calibrates the *overall* score to be within $\pm3$ points of the heuristic score, but it returns the *category breakdowns* directly from Gemini as-is.
* **Defect**: If Gemini scores `readability` or `keywords` at `70%` and the heuristic engine scores them at `90%` and `100%`, the client displays the uncalibrated Gemini breakdown, leading to visual mismatch alerts in the builder.

## 4. Proposed Fix Strategy

1. **Unify `isBoostCV` check**: Make `isBoostCV` check look for an invisible marker or metadata, or standard header fields, so it evaluates identically in both Builder and Scanner.
2. **Refine String Matches with Word Boundaries**:
   - Use word boundaries `\btable\b` instead of substring matching.
   - Restrict the `"|"` Canva check to only trigger if there are multiple pipes per line or if the file name is actually Canva.
   - Use word boundaries `\bskills\b` and `\btechnical skills\b` for the section sorting check so that `"EduSkills"` does not trigger it.
3. **Calibrate Category Breakdowns**: Calibrate the Gemini category breakdowns to remain consistent with the calibrated overall score.
4. **Enforce Evidence Presence**: Suppress any warning if it does not provide concrete triggering text from the parsed document.
5. **Automated Integration Test**: Implement a build test compiling a test resume, scanning it, and asserting the variance $\le 3$ points.
